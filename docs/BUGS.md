# Bugs fixed during the port

| # | Legacy location | Bug | Fix | Regression test |
|---|---|---|---|---|
| 1 | `App/v8xml/XmlSerializer.cpp` (TextXmlParser::readText, TextXmlWriter) | Leading whitespace in single-line strings was lost on save and reload, because the reader skips whitespace before text and the writer only uses CDATA for multi-line text | The writer encodes leading whitespace as numeric entities | `rbx-format` `xml::tests::keeps_leading_whitespace` |
| 2 | `App/v8xml/XmlSerializer.cpp` (TextXmlParser) | A missing child element (for example a Vector3 without `<Z>`) dereferenced a null pointer | Missing components read as 0 | covered by `rbx-format` place round-trip test |
| 3 | `content/fonts/characterR15.rbxm` | File damaged by LF to CRLF conversion before it was committed | Rebuilt by trying each ambiguous CR LF pair until every chunk decompresses and the chunk chain is complete | `rbx-format` `tests/places.rs` |
| 4 | `App/v8datamodel/MegaCluster.cpp` (autoWedgeCellScript) | The inverse corner wedge check read `sides[(n - 1) % 4]`, which is `sides[-1]` for `n = 0`, an out-of-bounds stack read | Uses `sides[(n + 3) % 4]`, the neighbor the code meant | `rbx-terrain` autowedge code path, covered by the terrain place runs |
| 5 | `rbx-format` XML reader (port) | Strings holding raw bytes written as `&#255;`-style entities became lossy UTF-8, which broke legacy `ClusterGridV2` terrain | Non-UTF-8 strings load as raw bytes and string properties keep them | `rbx-dom` `tests/terrain.rs` |
| 6 | `rbx-physics` assembly rebuild (port) | Offsets were built from a root CFrame that was slightly off orthonormal, so every rebuild squared the error until the assembly exploded | Root frame and offsets are orthonormalized | `rbx-physics` `tests/places.rs` (600 steps, all finite) |
| 7 | `rbx-physics` contact pairs (port) | A stale pair cleared its manifolds but kept parry's manifold workspace, whose sub-detectors then indexed the empty list and panicked in about 25 places | Clearing a pair also drops its workspace |
| 8 | `rbx-physics` workspace settings (port) | `PhysicalPropertiesMode` was mapped by position instead of by enum value (`Legacy` is 0, `Default` is 1), so Default places simulated with legacy densities and friction | Maps value 0 to Legacy and gives Workspace the legacy default of `Default` |
| 9 | `rbx-script` resume check (port) | Threads of disabled scripts were stopped at their first yield even when TestService had started them on purpose, so tests with a disabled TestService script never finished | TestService-started scripts skip the Disabled check, as in `TestService::startScript` |
| 10 | `rbx-physics` solver (port) | Bodies the solver doesn't simulate and has no cache for (the terrain ground body, anchored parts) got an identity inverse inertia because glam's `Mat3::default()` is the identity, so contacts far from the origin looked rotationally weightless and the velocity stage applied almost no impulse; resting assemblies kept gaining gravity velocity, slid too far and fell through terrain | Their mass and inertia are zero, as in `PGSSolver::initAnchoredObjects` |
| 11 | `rbx-script` LoadCharacter (port) | Characters were built from `character3.rbxm` without the `Humanoid::buildJoints` step, so they had no RootJoint, Neck, shoulders or hips; a character that fell even a few studs hit the humanoid's no-neck death check, broke apart and never walked | `load_character` builds the six R6 Motor6Ds and the Status object before parenting the model, as `Player::loadCharacter` does |
| 12 | `rbx-script` script rescans (port) | Rescanning scripts when the local player's Character changed stopped TestService scripts, because the normal run rules don't cover TestService; client tests were cut off as soon as their character spawned | Scripts that TestService started are skipped by the rescan |
| 13 | `rbx-physics` assembly rebuild (port) | Rebuilding assemblies after any joint change reset every assembly's kinematic flag, so a humanoid resting in RunningNoPhysics silently became dynamic while its state machine still treated it as kinematic | The rebuild restores the kinematic flag from each humanoid's state | `rbx-physics` `tests/humanoid.rs` `resting_humanoid_stays_kinematic_across_assembly_rebuilds` |
| 14 | `rbx-script` tween and render-step callbacks (port) | TweenPosition/TweenSize completion callbacks and BindToRenderStep functions always ran at GameScript identity, so core scripts' callbacks hit security errors; SettingsHub calls `GuiService:SetMenuIsOpen(false)` from its close tween callback inside `pcall`, the call failed silently, the menu stayed marked open, and every movement input after closing the Esc menu was delivered as Cancel | Callbacks run with the identity of the script that started the tween or bound the render step, as in legacy | `rbx-script` `tests/gui.rs` `tween_callbacks_keep_the_caller_identity` |
| 15 | `rbx-format` XML writer (port) | Color3 values were always written as a packed 8-bit ARGB integer, so a place saved to `.rbxlx` lost colour precision (0.75 came back as 0.749) | Colours an 8-bit value can't represent exactly are written as R, G and B floats, which the reader already accepted | `rbx-studio-ui` `tests/save_reopen.rs` `edits_survive_xml_save_and_reopen` |
| 16 | `rbx-render` moon (port, reproducing a legacy quirk) | Legacy `Sky.cpp` sets only `Color` for the moon and leaves `Color2` at the sun colour, so `sky.hlsl` tints the moon with the unclamped `lerp(sunColor, moonColor, worldY / 1700)`; the port drew the moon with the plain moon colour, so at night it was dimmer than in the 2016 client | Each moon vertex gets the same unclamped blend by its world height | visual; checked against `Sky.cpp` and `sky.hlsl` |
| 17 | `rbx-audio` web backend (port) | The threaded web build wrote samples with `AudioBuffer.copyToChannel` from a view of the shared wasm memory, which Web Audio rejects, so every buffer stayed silent | Samples are copied into the buffer's own channel arrays from `getChannelData`, which accept a copy from shared memory | heard in the browser |
| 18 | `rbx-script` Workspace arrow tool (port) | The engine's Studio arrow tool ran for every session without a local player, Studio included, and reselected on each mouse-down; pressing a Move, Scale or Rotate handle (which is not a part) cleared the selection before Studio's own tool saw the press, so handles could not be dragged | Studio documents set `host_selection`, and the engine skips its arrow tool when the host does its own selection | `studio` `drag_test::inserted_part_moves_with_handles_in_real_place` |
| 19 | `rbx-physics` humanoid floor search (port) | The floor raycast filter only accepted parts in the physics part list, so Terrain was never a floor; characters on terrain went to Freefall with their legs two studs into the ground | The filter and the floor validity check accept the terrain | `rbx-physics` `tests/humanoid.rs` `humanoid_stands_on_smooth_terrain` |
| 20 | `rbx-dom` BasePart.SpecificGravity (port) | The property always read 0, so scripts that sort parts by specific gravity (the buoyancy stability test) got the wrong answer | Computed from the material with the legacy `toSpecificGravity` table, shared with the buoyancy code | `CubeInWaterStabilityCheck.rbxl` |
| 21 | `rbx-physics` sleep stage (port) | A high-velocity new touch queued a recursive wake that ran after the solver, so a sleeping body hit at speed was solved as static for that step and the other body bounced off at exactly half its speed (the tank-versus-trees tests) | The contact recursive wake runs between the narrow phase and the solver, as `SleepStage` does before handing assemblies to the simulator; already-awake assemblies are left alone | `TankFliesAtTrees*.rbxl`, `DominoTest.rbxl` |
| 22 | `rbx-physics` CSG unions (port) | Unions whose PhysicsData was only the out-of-date placeholder were decomposed from their render mesh, which rounded their corners, so cubes rolled down slopes instead of sliding | Out-of-date unions collide as a block of their size (decision 135) | `rbx-physics` `tests/friction.rs`, `Slope*.rbxl` |
| 23 | Studio redraw (port) | A surface acquire failure reconfigured the surface but never requested the next frame, so Studio froze after load or after refocusing until the window was resized; when the fix reconfigured on every failure, an occluded window blocked on GPU idle each frame | Timeout and occlusion only skip the frame, occlusion pauses redraws until the window is visible, and only an outdated or lost surface is reconfigured | manual |
| 24 | `rbx-script` TestService (port) | `TestService.IsSleepAllowed` was ignored, so places that turn sleeping off for their run (the UberClock, character walking and buoyancy stress tests among them) let assemblies sleep anyway | Starting a run applies the setting to the physics world and finishing it restores the old value, as `TestService::setConfiguration` and `restoreConfiguration` do | `PhysicsTests/Character/Performance/*.rbxl` |
| 25 | `rbx-physics` auto-joins (port) | Wedges and corner wedges were joined as if they were blocks, using the part rotation and box faces, so a wedge's slope never welded and parts behind its slope welded to empty space; the corkscrew's 1152 thread wedges fell off the screw | Pairs involving a wedge or corner wedge use the polygon path of `Joint::canBuildJoint`: legacy face ids per shape, per-face frames, vertex and edge overlap tests and the doubled planar tolerance | `rbx-physics` `tests/joins.rs`, `PGS/Corkscrew.rbxl` |
| 26 | `rbx-physics` joint insertion (port) | A new weld or motor only moved its part when physics next stepped, so a script that built a mechanism and read part positions straight away (with RunService paused, as the UberClock tests do) saw the unsnapped positions | Reading a part's CFrame or Position settles pending joints first: a part joined alone to an assembly is placed from the joint at once, anything else rebuilds the assemblies, matching legacy where a joint snaps its part as it enters the world | `PhysicsTests/General/UberClock1.rbxl` accuracy check |
| 27 | `rbx-physics` joint hooks (port) | Resizing a part or editing a joint's C0 and C1 ran a full physics sync even for parts and joints outside Workspace, so building a model out of cloned parts before parenting it slowed down with every part | The hooks return early for instances that are neither in Workspace nor known to physics; joining also flushes the spatial index first so it sees parts added in the same frame | `PhysicsTests/General/UberClock1.rbxl` setup time |
| 28 | `rbx-script` Workspace:GetNumAwakeParts (port) | Returned the number of parts in awake assemblies, while legacy sums the kernel's body counts, one per awake assembly, so a falling welded pair counted twice | Counts awake assemblies | `Confirm NO Premature Sleep With Supporting Block Deletion.rbxl` |
