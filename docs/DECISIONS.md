# Decisions

Decisions made during the port that `docs/GOAL.md` doesn't cover.

| # | Decision | Reason |
|---|---|---|
| 1 | Rust 1.99.1 pinned in `rust-toolchain.toml` | latest stable at the start of the port |
| 2 | The web build uses `RUSTC_BOOTSTRAP=1` with `-Z build-std` instead of a separate nightly toolchain | wasm threads need std rebuilt with atomics; this keeps one pinned compiler |
| 3 | CI checks out the repo without `legacy/` | saves Actions minutes and disk while the C++ still exists |
| 4 | Docker runs through colima on this Mac | that's the installed Docker setup |
| 5 | The class, property, function, event and enum list in `crates/rbx-reflection/data/api.json` was generated once from the legacy C++ reflection declarations (descriptor templates, macros and enum definitions) and is checked in | the legacy tree gets deleted, and the data is what the engine's API is made of |
| 6 | `rbx-format` works on an untyped tree; `rbx-dom` converts values to the declared property types | the XML format stores BrickColor as `int` and the binary format stores every string kind the same way, so only the reflection data can tell them apart |
| 7 | XML saves write non-ASCII text as UTF-8 instead of one numeric entity per byte | both forms load the same; UTF-8 is readable and valid XML |
| 8 | `.gitattributes` marks place files, images, fonts and audio as binary | two R15 character models in the original repo were damaged by line-ending conversion |
| 9 | Default property values come from `crates/rbx-dom/data/defaults.json`, generated once from the legacy constructors by following each property getter to its member and initializer, plus a hand-written table in `defaults.rs` for values the generator couldn't resolve | about 370 defaults resolve automatically; the rest depend on physics primitives or helper functions |
| 10 | `rbx-dom` reaches physics through a `WorldHooks` trait that `rbx-physics` implements | part setters in the legacy code break and rebuild joints and nudge parts out of overlap, which needs the physics world, but the instance tree can't depend on physics |
| 11 | Instance events go into a log that each subsystem drains, instead of synchronous callbacks | Rust can't hand out a mutable instance tree to listeners in the middle of a change; scripts still get their event handlers run before control returns to them |
| 12 | `humanoidAnimateR15.rbxm` is left out of the place tests (listed in `tests/excluded_places.txt`) | it was already damaged in the original repository, so the legacy engine couldn't load it either |
| 13 | The service list in `rbx-dom` comes from the legacy classes that inherit the Service mixin | the reflection data doesn't record that mixin |
| 14 | Physics always uses the PGS solver; the legacy spring kernel (`App/v8kernel` connectors) isn't ported | `docs/GOAL.md` picks the PGS solver; the spring kernel was the fallback when `PGSPhysicsSolverEnabled` was off |
| 15 | Motors, Motor6D and VelocityMotor stay kinematic links inside an assembly, as in the legacy body tree, and keep the legacy quirk that the link runs from the tree parent's C to the child's C | that's how the legacy engine animated characters even with PGS on; matching it keeps character rigs and animations behaving the same |
| 16 | Glue and ManualGlue become four breakable ball-in-socket constraints at the glued face's corners, breaking at the legacy joint force | with PGS on the legacy glue connectors were never handed to the solver, so glue did nothing; the spring kernel's breakable glue is the behavior players knew |
| 17 | BodyPosition, BodyGyro, BodyVelocity and BodyAngularVelocity drive PGS constraints against the ground body (linear spring with time-step-corrected P and D, body angular velocity with the gyro's instability damping, linear velocity, legacy angular velocity), and any body mover property change tickles its assembly recursively; BodyForce, BodyThrust and RocketPropulsion stay force-based, RocketPropulsion with P and D divided by 19 | the 2016 test places only pass with `PGSUsesConstraintBasedBodyMovers` and `PGSWakePrimitivesWithBodyMoverPropertyChanges` on, so the shipped settings had both on although the code defaults are off; the force-based controllers at 240 Hz are too weak (PGS scale) or unstable (spring-kernel gains) |
| 18 | `PhysicalPropertiesMode` follows legacy `World::getUsingNewPhysicalProperties`: `New` uses the material density, friction and elasticity table, while `Legacy` and `Default` use unit density and the part's Friction and Elasticity, because `MaterialPropertiesNewIsDefault` keeps its code default (off) | the 2016 test runner ran with code-default flags, and the Default-mode physics tests (sleeping movers, slopes, friction) only pass with legacy properties; the flag-aware material tests read the flags themselves |
| 19 | Collision detection uses parry3d contact manifolds with zero prediction distance and keeps the legacy 0.05 stud penetration margin in the solver | parry replaces the hand-written Block/Ball/Poly contact code; the margin is what keeps resting contacts stable in the legacy solver |
| 20 | Wedge and corner wedge collision shapes are convex hulls of the legacy mesh vertices; blocks, wedges and corner wedges use the legacy hollow-box moment of inertia and full box volume, with the legacy center-of-mass offsets for wedges | `Block`, `WedgePoly` and `CornerWedgePoly::getMoment` all used the hollow-box formula and `Geometry::getVolume` returned x·y·z for wedges, so a wedge weighed as much as a block of the same size |
| 21 | The reflection extractor now also reads the 24 surface properties declared with `SurfacePropDescriptor` templates in `Surface.cpp` | the first extraction missed them, and auto-joins need TopSurface and the rest |
| 22 | Joints broken in the solver (glue pulled apart) get destroyed, like legacy JointInstances removed when their connector broke | scripts see the joint disappear the same way |
| 23 | Fast flag defaults live in `crates/rbx-base/data/flags.json`, generated once from every `FASTFLAGVARIABLE`-style declaration in the legacy code; a short list in `flags.rs` overrides the flags whose behavior the port always has (PGS on, material properties enabled, fixed TouchEnded reporting) | scripts call `settings():GetFFlag` and expect the shipped answers, and unknown flags must still raise "Flag X does not exist" |
| 24 | The `TestLocalUser` permission is treated as `LocalUser` | that's its value in shipping builds; only the internal test build mapped it to `None` |
| 25 | The place test runner starts test scripts with the `LocalGUI` identity, runs normal scripts too, gives each place `TestService.Timeout` plus two seconds, and runs places without tests for 5 game seconds | that's what `RobloxTest/Tests.cpp` did (`Impersonator(LocalGUI_)`, `EmptyTester`) |
| 26 | Script resumes get a watchdog (`ScriptContext:SetTimeout`, a Luau interrupt) that raises "Game script timeout" for game-script identities; the test runner sets it to 10 seconds | same rule as the legacy hook; it keeps one runaway test from hanging the whole run |
| 27 | Humanoids live in `rbx-physics` (state machine, floor rays, ladder search, forces) and the script layer only forwards API calls and fires the signals | the legacy Humanoid was a kernel connector that read and wrote bodies every world step; keeping it next to the bodies avoids a lock round trip per force |
| 28 | Assembly roots use the legacy size multipliers: `HumanoidRootPart` x10, `Torso` x5, seats x20 | that's what `PartInstance::setName` and `ActionStation` set, and humanoid movement needs the root part to be the assembly root |
| 29 | A non-saved property that shares its getter with a saved one on the same class is an alias of it (Humanoid `Health` and `Health_XML`) | both descriptors read the same member in the legacy code, so they must share storage |
| 30 | Terrain lives in its own crate, `rbx-terrain`: the legacy voxel grid (32x16x32 chunks, ClusterGrid V1/V2/V3), the smooth grid (32^3 chunks with mips), the smooth mesher and the legacy-to-smooth conversion | the DataModel, physics, the script API and the renderer all need it, and none of them should own it |
| 31 | The DataModel decodes terrain properties into live grids when they are set and keeps the raw bytes; it re-encodes only after an edit | saving an untouched place gives back the exact bytes the file had |
| 32 | Physics keeps a mirror of the terrain grid and refreshes it from the grid's change log once per world step | queries and contacts run without holding the DataModel, and scripts that edit many cells between steps cost one refresh |
| 33 | Legacy terrain collides through one parry convex shape per cell (cube and the four wedge shapes, rotated about Y); smooth terrain collides through one triangle mesh per 8^3 chunk built by the ported mesher, using only solid triangles | same shapes and chunking as `MegaClusterPoly` and `SmoothClusterGeometry`, which fed Bullet the same data |
| 34 | The smooth mesher computes vertex seeds with 32-bit `size_t` hashing | the 2016 Windows client was 32-bit; the seed only moves vertices of deformed materials |
| 35 | Buoyancy is ported as forces in the world step with the legacy kernel timestep (1/4560 s) inside the viscosity term | the legacy connector ran every kernel step; keeping its constant keeps the drag the tests calibrated against |
| 36 | Unions whose `PhysicsData` is a placeholder or an old version get collision hulls rebuilt from their mesh with parry's V-HACD (concavity 0.05, at most 64 hulls), cached per mesh | legacy rebuilt them with Bullet's ConvexDecomposition (depth 6, 5% concavity); Bullet isn't part of the port, and V-HACD gives the same kind of convex set |
| 37 | Unions whose mesh and physics keys point at dictionary entries the file doesn't contain collide as their bounding box | the data is gone; legacy left such parts without collision geometry, which made them fall through the world |
| 38 | Union mass and inertia use the part's box volume and a hollow-box moment, scaled by `Size / InitialSize` (uniform for symmetric unions) | same as `TriangleMesh::getMomentHollow` and `PartOperation::calculateSizeDifference` |
| 39 | Where the legacy reflection differs between the shipping build and `RBX_TEST_BUILD`, the port follows the test build (today only `Workspace.PhysicalPropertiesMode` being scriptable, plus the TestService command functions) | the legacy place tests ran in the test build and read these members |
| 40 | Legacy terrain rays walk cells with the original `hitTestMC` stepping: a ray that starts in water stops where the water state changes, block faces are tested one-sided in the legacy order, hits at distance 0 count as misses, and legacy terrain reports `Grass` as the hit material | `RaycastTest` compares exact hit points, and `ContactManager` dropped terrain hits that weren't strictly inside the ray |
| 41 | Smooth terrain water is hit through the mesher's water triangles kept in a second triangle mesh per chunk, used only by ray casts | same split as `ChunkMeshShape`, which kept a solid tree and a water tree |
| 42 | `Tool` keeps the legacy backend state machine (NOTHING to EQUIPPED) in a `DataModel` side table and watches the character and torso through a child-change hook in `set_parent`; the DataModel carries `backend_processing` and `frontend_processing` flags, both on until networking sets them | legacy connected to `childAddedSignal` on those instances; the flags replace `Players::backendProcessing` and `frontendProcessing` |
| 43 | The place round-trip test loads documents with both processing flags off | equipped tools build a `RightGrip` weld when their character enters the tree (as in legacy Studio), so a gameplay-enabled load isn't idempotent; the round trip checks the file format, not gameplay |
| 44 | Missing members starting with a lowercase letter fall back to the capitalized member and print the legacy camelCase warning (at most 100 times) | `LuaInstanceBridge` did this for old scripts such as `setJobsExtendedStatsWindow` |
| 45 | `Seat` and `VehicleSeat` share one behavior ported from `SeatImpl`: seat touches create the `SeatWeld`, weld add and remove drive `Occupant`, `SeatPart` and `Sit`, and leaving the Seated state destroys the weld; the 3 second sleep uses game time | the legacy template ran the same code for both classes; game time keeps test runs deterministic |
| 46 | `Occupant` and `Humanoid.SeatPart` live in a DataModel side table and are served as computed properties | they have no storage slot in the reflection layout (runtime-only, not saved) |
| 47 | `VehicleSeat` drives every `Rotate` hinge that touches the seat's assembly and lines up with the seat's right vector, using the legacy lookup table and `Torque * 1000` torques inside the world step | same rules as `VehicleSeat::stepHinges`; the legacy seat was a joint in the kernel that applied torques each step |
| 48 | The 48 `.clienttest` files live next to their server places in `tests/places` and run in phase 4 with the multiplayer harness; until then the round-trip test only checks that they load and save | the legacy runner opened them only inside client processes spawned by a multiplayer server test, so they need rbx-net |
| 49 | Loading a place for simulation runs the legacy `World::joinAll` pass: every part with a non-smooth surface builds surface joints to the parts it touches, creating joint instances under `JointsService` | `DataModel::processAfterLoad` did this after every file read; the test places rely on these joints (Motor and Hinge surfaces are never saved as instances) |
| 50 | Parts joined by any joint never get a contact between them | legacy `ContactStage` kept the contact out of the kernel while a joint linked the same two primitives |
| 51 | The place test harness gives `tick()` a virtual clock: wall time at load plus game time plus the wall time scripts have observed inside frames (each frame's peak is carried into the next), never going backwards | the harness steps faster than real time, and tests compare `tick()` with `wait()`; the in-frame wall time keeps busy loops on `tick()` moving, and carrying it keeps later readings at least the elapsed game time ahead of earlier ones |
| 52 | DataModel code reports legacy `StandardOut` messages through a queue the script runtime drains into the output | the DOM has no access to the engine's output, and warnings such as the FormFactor deprecation notice come from DataModel setters |
| 53 | `JointsService` join-after-move (`ManualJointHelper`) ships with Studio in phase 8 | it is Studio's join-on-drag tool and needs the face-matching and terrain cell helpers that the Studio tools also use |
| 54 | RunService has the legacy run states: Run simulates and starts held scripts, Pause stops simulation but keeps scripts, Stop and Reset stop every backend script except CoreScripts and TestService scripts and hold new ones until the next Run; the harness only runs a test place on load when `TestService.AutoRuns` is on | `RuntimeScriptService::onRunState` held backend scripts while stopped, and `TestService::run` only called `RunService:Run` when AutoRuns was set |
| 55 | Scripts with a `LinkedSource` run the linked content instead of their embedded Source; test places can find web assets in `tests/assets/<id>` | `Script::requestCode` used the cached remote source whenever the script was linked; the original roblox.com assets are gone, so the few tests that need one get a local file that does what the test checks |
| 56 | While scripts handle the ChildAdded, ChildRemoved, DescendantAdded, DescendantRemoving and AncestryChanged events of a reparent, setting that instance's Parent prints the legacy warning and does nothing | legacy fired those events inside `Instance::setParentInternal`, where a nested reparent hit the `isSettingParent` check; our events are dispatched after the change, so the runtime keeps the same rule during dispatch |
| 57 | Loading a place that uses new physical properties gives every part with a non-default legacy Friction or Elasticity custom physical properties (material density, its Friction, its Elasticity) | `DataModel::processAfterLoad` ran `PartInstance::convertToNewPhysicalPropRecursive` so old places kept their tuned friction |
| 58 | Sleep follows the legacy `SleepStage` neighbor rules: joints and touching contacts link assemblies, a resting assembly sleeps deeply only when no neighbor is awake (otherwise it sleeps while checking and is re-evaluated every fourth step), waking an assembly makes its deep-sleeping neighbors check again, velocities are zeroed on sleep and on wake, contact separation wakes both sides, new touches above 1 stud/s and body mover force changes wake recursively to depth 8 | same states and transitions as `SleepStage::stepSleepStage` and `BodyMover::stepWorld` with the PGS solver |
| 59 | The wire format is postcard-encoded `Message` values; every instance is named by a `NetId` (the creating peer in the top 16 bits, that peer's local id below), references inside property values travel as NetIds and resolve when the target arrives | legacy used RakNet bitstreams with GUIDs and property dictionaries; postcard keeps the format compact and versioned through `PROTOCOL_VERSION`, and peer-scoped ids need no allocation round trip, like the legacy GUIDs |
| 60 | The replicator works from DOM events and the current state: each peer has a view of the instances it knows with their parents, a change sends `New`, `Parent`, `Property` or `Delete` by comparing that view with the DataModel, and changes applied from a peer are flushed to every other peer but not back to the sender | it keeps the legacy replicator's top replication containers, class replication flags (`INTERNAL_PLAYER` only to the owning player) and echo rules without porting the RakNet item queues |
| 61 | The server checks every change from a client with the legacy filters: the basic `NetworkFilter` when `Workspace.FilteringEnabled` is off and `StrictNetworkFilter` when it is on, after the `ServerReplicator` checks (no `Message`, one `Player` per client, no `Source` or `LinkedSource`, no Player identity changes) | the filtering and ownership model must stay the same as the 2016 engine |
| 62 | RemoteEvent and RemoteFunction arguments travel as `RemoteValue` (a Variant, an array, a string-keyed map or a typed enum item); tables with an array part become arrays with nil holes kept, other tables keep only their string keys, functions and userdata become nil | matches the legacy Reflection tuple conversion that `RemoteFunctionsAndEvents` checks value by value |
| 63 | Remote events with no listener and remote function calls with no callback wait in a queue of at most 256 per instance and run when a listener connects or the callback is set; play solo fires them locally | `DFInt::RemoteDelayedQueueLimit` and the delayed invocation queues in `Remote.cpp` |
| 64 | Multiplayer test places run in one process: the server and each client get their own engine and script runtime, connected by in-memory links that carry encoded packets; clients load the `.clienttest` file, create `Player1..N`, and their TestService results count toward the place | the legacy runner started the server headless and spawned one client process per player with `--client_test`; one process keeps the test harness portable and deterministic |
| 65 | Native clients reach game servers over QUIC (quinn, ALPN `rbx/1`): reliable messages go on one bidirectional stream as length-prefixed frames, physics goes in datagrams when it fits, and the server presents a self-signed certificate that clients check against a SHA-256 hash from the admin API | RakNet's reliable and unreliable channels map onto QUIC streams and datagrams; hash pinning gives encryption and server identity without a certificate authority, and the same hash scheme works for WebTransport in browsers |
| 66 | The server ports every RCCService SOAP operation to an HTTP/JSON route (`/v1/hello`, `/v1/version`, `/v1/status`, `/v1/jobs` open, list and close-all, `/v1/jobs/{id}` info, execute, renew, expiration, diag and close, `/v1/jobs/close-expired`, `/v1/batch`), with an optional bearer token; Lua values come back as JSON | same job model as `CWebService`; JSON replaces gSOAP's LuaValue arrays |
| 67 | `NetworkServer:Start` and `NetworkClient:PlayerConnect` queue a request that the host (server job, player app or test harness) carries out, and `NetworkClient.Ticket` carries the server certificate hash | scripts keep the legacy join and gameserver flow while the host owns sockets and threads |
| 68 | The server assigns network ownership with the legacy `NetworkOwnerJob` rules: a character's parts belong to its player, other moving assemblies go to the closest player whose simulation radius covers them and switch only when another player is closer, and manual owners stay until they leave; owners send root-part state every second frame and the server accepts state only from the owner | keeps the distributed physics ownership model of the 2016 engine |
| 69 | The arbiter speaks the same `/v1` API as the server and proxies each job to one server process (one job per process by default, like `SetMultiProcess(true)`), keeps `recycle_queue_size` processes warm, kills a process when its job closes, and replaces any process that misses `failures_before_restart` health checks; its own stats and settings live under `/v1/arbiter` | ports `JobManager` and `RccServiceMonitor`; the launcher is a trait so tests can run servers in process |
| 70 | Network ownership belongs to ownership groups: moving assemblies joined by non-rigid joints, cut at anchored assemblies, rooted at the assembly that touches an anchored one (or the heaviest); every part keeps its owner and rule, a group whose parts disagree falls back to automatic server ownership, and parts that become anchored drop their entry | this is the legacy root moving primitive model, and keeping the value on every part reproduces `checkConsistentOwnerAndRuleResetRoots` when joints break, join or anchor |
| 71 | A multiplayer test place passes or fails on the server's TestService result; client checks, client errors and clients that never joined go to the output | the legacy runner terminated the client processes when the server test finished and never read their results, and several `.clienttest` scripts fail on their own (one calls a function before defining it) |
| 72 | The Stats service builds the legacy StatsItem tree on first use (Workspace FPS and World counts, Lua threads, DataModel instances, and one Network item per connected peer with sent and received packet and byte rates); `GetJobsInfo` reports the heartbeat, physics, Lua and per-peer network send jobs | test places read these values through `stats()` and `game:GetJobsInfo()`; the reflection data was missing `StatsItem:GetValue` and `GetValueString`, so they were added from `Stats.cpp` |
| 73 | Each frame resumes due `wait()` threads in wake order until `settings().Lua.WaitingThreadsBudget / 60` seconds of wall time have passed, always at least one, and leaves the rest for the next frame; `stats().Lua.ThreadsThrottled` is the 0.05 running average of frames that hit the budget | same rule as `ScriptContext::resumeWaitingScripts` and `YieldingThreads::resume` |
| 74 | HttpService, `game:HttpGet`/`HttpPost` and `MarketplaceService:GetProductInfo` share one web layer: URLs on the old roblox.com hosts are rewritten to the configurable base URL (`ContentProvider:SetBaseUrl`, default the local server), local fixtures in the asset folders (`productinfo/<id>.json`, asset ids) answer first, and other requests run on a worker thread while the calling Lua thread yields; HttpService keeps the legacy checks (HttpEnabled, game server only, 500 requests a minute) | GOAL asks for one configurable base URL and a local development server instead of hardcoded roblox.com endpoints; the old web services are gone, so test places get fixtures like the linked-source assets |
| 75 | Admin API `execute` runs the script to completion, stepping the job while it yields, with a 60 second limit | RCCService `Execute` returned the script's results, and scripts that call yielding APIs would otherwise return nothing |
| 76 | Setting C0 or C1 on a rigid joint rebuilds that assembly and writes the new part frames back at once, and terrain edits wake the parts that touch the changed cells | legacy read non-root part frames from the assembly root on demand, so scripts saw the moved part right after the property set, and `MegaClusterInstance` cell changes woke touching primitives |
| 77 | The renderer draws parts with instancing: each distinct part geometry (shape, size, surfaces, studs, tiling) is generated once in local space by the ported `GeometryGenerator` and drawn with per-part transforms, color and material data, instead of baking world-space vertices into clusters | same vertex data and shading as `FastCluster` geometry, with far less CPU work per frame and per moved part |
| 78 | Shading follows `default.hlsl` in its HQ form (per-pixel specular, edge outlines, fog) and renders in gamma space like the D3D9 engine; DXT textures are decoded on the CPU so every backend, WebGPU included, gets the same RGBA data | keeps the 2016 look on Metal, Vulkan, DX12 and WebGPU without depending on BC texture support |
| 79 | Smooth terrain is meshed per 32x16x32 chunk with the ported `Voxel2::Mesher` and drawn with its own pipeline; the per-corner atlas UVs that `smoothcluster.hlsl` computed in the vertex shader from the material constant table are computed on the CPU into the vertex, and only edited chunks are remeshed using the grid change log | WGSL has no indexed constant table matching the D3D9 layout, and computing the three corner UVs once per vertex keeps the shader simple while giving the same texture blend |
| 80 | Water (smooth water triangles and legacy water cell faces) uses one translucent water shader driven by `Terrain.WaterColor` and `WaterTransparency` with lambert, specular and a fresnel term | the legacy water shaders need the reflection and refraction passes that this renderer does not have yet; this keeps water visible and tinted the way places set it |
| 81 | Text uses the bundled TrueType fonts through ab_glyph with the `TypesetterDynamic` layout rules (line breaking, kerning, alignment, legacy 1.5x height for the Legacy font, the ratio search for TextScaled); the fonts are compiled into rbx-text so the server, client and web build measure text the same way | FreeType is C; the dynamic typesetter was the 2016 default (`UseDynamicTypesetterUTF8`), and TextBounds, TextFits and TextService results have to match what the renderer draws |
| 82 | GUI placement (AbsolutePosition, AbsoluteSize, canvas and clip rects) is computed from the DataModel on demand from the current screen size and GuiService inset instead of being cached on each instance and updated through resize events | the values always match the properties scripts just set, without porting the `handleResize` propagation |
| 83 | wgpu stays the graphics layer, but native backends are the primary target: each platform runs one native API (DX12 on Windows, Metal on Apple, Vulkan on Linux and other Unix, browser WebGPU only for wasm), the OpenGL backend is not compiled, desktop devices request native-only features the adapter offers (BC texture compression first, uploading DXT textures compressed instead of decoding them on the CPU), and headless rendering falls back to the platform's software adapter (WARP, lavapipe) | the owner wants real Vulkan, DX12 and Metal rendering rather than a WebGPU-first design; wgpu issues native API calls directly, and native features are used wherever the web profile would hold them back. Supersedes the CPU decode part of decision 78 on desktop |
| 84 | The GUI is laid out in logical pixels (window size divided by the OS scale factor) and drawn scaled, with glyphs rasterized at the physical size | 2016 GUIs were authored for 1x pixels; this keeps their layout on HiDPI screens while text stays sharp |
| 85 | The client starts the 2016 core GUI the way `StudioConfigurer::configure` did: the scripts/Modules tree becomes ModuleScripts under CoreGui.RobloxGui.Modules, the engine builds RobloxGui.ControlFrame like `GuiBuilder::buildLuaGui`, ServerStarterScript runs where the backend runs and StarterScript where the frontend runs, and core script sources load from assets/content/scripts | the topbar, chat, player list, backpack, settings menu and notifications are all Lua in the 2016 client and need these engine pieces to start |
| 86 | Feature flags that the 2016 production client received from the web (in-game topbar, Lua bubble chat, new dev console, SetCore hooks, player drop down, server followers and related ones) default to their production values instead of the compiled-in defaults | without the web settings service the compiled defaults would bring back the pre-topbar 2014 GUI |
| 87 | R6 characters render like the 2016 `MaterialGenerator`/`GeometryGenerator`: body parts that pass `HumanoidIdentifier::isBodyPartComposited` are replaced by the baked torso/arm/leg meshes (or CharacterMesh meshes), and body colors, the head color and face decals, shirt, pants, t-shirt and character mesh textures are composited into a 1024x512 texture with the Composit*.mesh layouts, the 1365x512 canvas projection and the legacy blit and premultiplied blend modes | plain blocks with studs are how characters looked before texture compositing; this is the 2016 look and the path clothing needs |
| 88 | Text glyph quads are sized from the glyph rasterized at the output resolution and positioned from the pen and baseline, snapped to output pixels | scaling 1x glyph boxes onto 2x bitmaps stretched and shifted letters on HiDPI screens |
| 89 | The player and game server load the keyframe Animate script only when the default animation assets (180435571 and the rest, web assets in 2016) resolve from the local asset folders, and otherwise the procedural `humanoidAnimateLocal.rbxm` Animate that ships in content/fonts; the test harness keeps the exact legacy choice | the keyframe animations were never part of the shipped content, so without the web service characters would stand frozen; dropping the assets into an asset folder restores the keyframe animations |
| 90 | The game server runs ServerStarterScript when it has a content folder | it creates the RobloxReplicatedStorage remotes the 2016 core GUI waits for (dialogs, followers) |
| 91 | Global shadows use a port of the 2016 voxel light grid: parts and terrain are voxelized into 4-stud occupancy cells with the `Voxelizer` distance functions, sun visibility and skylight are propagated per 32x16x32 chunk with the legacy fixed-point kernels and inter-chunk fringes, skylight is scaled by OutdoorAmbient minus Ambient, and an 8x4x8 chunk window around the camera focus is stored in a wrapped 3D texture that the part, terrain and water shaders sample like `lgridSample`; the window updates a budget of chunks per frame and offscreen renders converge fully | this is how 2016 Roblox drew shadows and outdoor ambient when GlobalShadows is on (126 test places use it); parts are voxelized on all quality levels, like the high-quality setting with non-fixed parts enabled |
| 92 | Characters cast shadows through a port of the 2016 `SceneManager` shadow map: humanoid parts render light-space depth into a 1024x1024 map (0.2 studs per texel, 64-stud depth range, origin snapped to texels), two 7-tap Gaussian passes keep the minimum depth and blur coverage with shadowmask.png, and every surface applies `shadowSample` scaled by the sun-height shadow intensity; PointLight, SpotLight and SurfaceLight feed the light grid colour channels with the legacy attenuation kernels and 3-axis blur, without the per-light shadow masks | matches how 2016 drew character shadows on all quality levels and how dynamic lights reached the world; per-light shadow masks are a separate pass used only when a light sets Shadows |
| 93 | The sky follows the 2016 `Sky` renderer: skybox texels are tinted by the time-of-day sky colours along height, the sun (drawn three times) and moon are additive camera-facing billboards sized from SunAngularSize/MoonAngularSize, and the star field uses the legacy counts, colours, brightness bands from the moon height and twinkle refresh every 40 frames, with stars drawn as 2-pixel quads | WebGPU has no point size, so stars are quads with the same on-screen size |
| 94 | Particles port the 2016 `Emitter` simulator and its effect presets: Fire, Smoke, Sparkles and ForceField use the `ParticleEmitter` settings, Explosion uses the `ExplosionEmitter` core, sparks, shockwave, smoke and implosion emitters, and the ParticleEmitter instance uses the `CustomEmitter` curves; particles are simulated on the CPU with the legacy forces, spread, spin, growth and distance throttling, expanded into camera-facing quads, and drawn with the five legacy particle shaders and blend modes after transparent geometry. `ParticleEmitter:Emit` adds to a per-instance count that the renderer turns into bursts | the renderer reads the DataModel without a signal path back from scripts, so emit requests are counted instead of delivered as events |
| 95 | ParticleEmitter is creatable and `CustomEmitterRenderEnabled` defaults to on | the legacy class is `DescribedCreatable` (the API dump missed it because of a typedef), and ParticleEmitter shipped to production in 2016 |
